# Design: โหมดจั่วไพ่บนเว็บ + จัด flow/ปุ่มใหม่

วันที่: 2026-11-03 · สถานะ: ร่างรอเจ้าของร้านอนุมัติ

## 1. ที่มาและเหตุผล

เว็บนี้ผู้จัดกิจกรรมที่ร้านเป็นคนกดใช้งาน (ลูกค้าบางคนกดเองด้วย) ปัจจุบันมีแค่ flow เดียวคือ "ลูกค้าจั่วไพ่จริง แล้วมาเลือกบนเว็บว่าได้ใบไหน" ซึ่งมีปัญหา 2 ข้อ

1. **ไม่รองรับกรณีไม่มีไพ่จริง** ผู้จัดอยากให้ลูกค้ากดเล่นเองจนถึงหน้าผลลัพธ์ได้เลย แล้วผู้จัดทำนายตามที่ได้
2. **ปุ่มซ้ำซ้อน เข้าใจยาก** (ผู้จัดบอกเอง) หน้า Landing กับ SiteNav มีปุ่มที่พาไปที่เดียวกัน
   - Hero: "เลือกไพ่ที่ได้" (`/pick`) และ "ดู character ทั้ง 22 ตัว" (`/characters`)
   - SiteNav: "เลือกไพ่" (`/pick`) และ "Character" (`/characters`)
   - หน้าผลลัพธ์: ลิงก์ "เลือกไพ่ใหม่" ซึ่งไม่ตรงกับโหมดที่เพิ่งเล่น

### เหตุการณ์ใช้งานจริงสองแบบ
- **โหมดจั่วบนเว็บ:** แนะนำให้ลูกค้ากดเล่นเองจนถึงหน้าผลลัพธ์ ไม่ต้องใช้ไพ่จริง ผู้จัดอ่านคำทำนายตามที่ได้
- **โหมดไพ่จริง:** ผู้จัดสับไพ่จริง แล้วกดเลือกไพ่บนเว็บให้ลูกค้า หรือให้ลูกค้ากดเอง ผู้จัดอ่านคำทำนายตามที่ได้

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย

**เป้าหมาย**
- เพิ่มโหมดจั่วไพ่บนเว็บ (เว็บสุ่มไพ่) พร้อมแอนิเมชันสับสำรับ
- เก็บโหมดไพ่จริง (กริดเลือกไพ่) ไว้ใช้งานเหมือนเดิม
- ลดความซ้ำซ้อนของปุ่ม ให้ผู้จัดรู้ว่าต้องกดอะไรต่อในทุกหน้า

**ไม่ใช่เป้าหมาย**
- ไม่แก้เนื้อหาไพ่, คำทำนาย, ซอส, character, โปสเตอร์ และตาราง mapping ใน `data/`
- ไม่ทำระบบจำโหมดข้ามรอบ ไม่ทำระบบล็อกอิน ไม่เก็บสถิติ
- ไม่เพิ่มจำนวนใบที่จั่ว (จั่วทีละ 1 ใบเท่านั้น)

**ข้อที่ถือว่าล้มเหลว (anti-goal)**
- ผู้จัดยังต้องคิดว่า "ปุ่มไหนพาไปไหน"
- แอนิเมชันสับเกิน ~1.5 วินาที ล็อกการกด หรือกระตุกบนมือถือ
- คำทำนายของโหมดจั่วบนเว็บต่างจากโหมดไพ่จริงสำหรับไพ่ใบเดียวกัน

## 3. ข้อจำกัด
- ทำตาม CLAUDE.md: mobile-first, UI ภาษาไทย, animate เฉพาะ `transform`/`opacity`, เคารพ `prefers-reduced-motion` ผ่าน `MotionProvider`, ห้ามเช็ก `useReducedMotion` ใน `initial` ของคอมโพเนนต์ที่ SSR, ห้ามบล็อกการกดข้าม
- ตาราง mapping อยู่ใน `data/` เท่านั้น ห้าม hardcode ใน component
- Next.js เวอร์ชันนี้ต่างจากที่รู้จัก อ่านคู่มือใน `node_modules/next/dist/docs/` ก่อนเขียนโค้ด (ตาม AGENTS.md) และโปรเจกต์ใช้ `cacheComponents` (มี Activity เก็บหน้าไว้ ดูคอมเมนต์ใน `components/CardGrid.tsx`)
- ไพ่ใช้ 22 ใบตายตัว (ห้ามเพิ่ม/ลด/เปลี่ยนชื่อ)

## 4. Flow ใหม่ (ที่เจ้าของร้านตัดสินใจ)

```
Landing ──[เริ่ม]──▶ เลือกโหมด ─┬─ จั่วบนเว็บ ──▶ สับ+แผ่พัด ──▶ แตะเลือก 1 ใบ ─┐
                                └─ ไพ่จริง ──▶ กริดเลือกไพ่ (เดิม) ─────────────┤
                                                                               ▼
                              PickTransition (เดิม) ──▶ หน้าคำทำนาย/โปสเตอร์/ซอส (เดิม)
                                                                               │
                                                  [แชร์/ดาวน์โหลด]  [เล่นใหม่ ──▶ เลือกโหมด]
```

### 4.1 Landing
- มีปุ่มหลัก **ปุ่มเดียว** คือ "เริ่ม" พาไปหน้าเลือกโหมด
- เอาลิงก์ "ดู character ทั้ง 22 ตัว" ออกจากหน้านี้

### 4.2 หน้าเลือกโหมด (หน้าใหม่)
- การ์ด/ปุ่มใหญ่ 2 อัน อธิบายสั้นๆ ว่าแต่ละโหมดคืออะไร
  - **จั่วบนเว็บ** (ไม่ต้องมีไพ่จริง)
  - **เลือกไพ่ที่จั่วจริง** (ผู้จัดสับไพ่จริงแล้วเลือกบนเว็บ)
- ไม่จำโหมดที่เลือกครั้งก่อน (ถามทุกรอบ)

### 4.3 โหมดจั่วบนเว็บ
- เริ่มด้วยสำรับคว่ำ 1 กอง มีปุ่ม/ข้อความให้กดสับ
- กดแล้วเล่นแอนิเมชันสับ (หัวข้อ 5) จบด้วยไพ่คว่ำแผ่เป็นพัดทั้ง 22 ใบ
- ลูกค้า (หรือผู้จัด) แตะเลือกไพ่ **1 ใบ** จากพัด
- เว็บเป็นฝ่ายกำหนดว่าไพ่ใบนั้นคือใบไหน และกลับหัวหรือไม่:
  - สับ (สุ่มลำดับ 22 ใบ) ครั้งเดียวตอนกดสับ ใบที่แตะได้คือใบที่อยู่ตำแหน่งนั้นในลำดับที่สับแล้ว
  - **กลับหัวสุ่มอัตโนมัติประมาณ 30%** ไม่มีสวิตช์ให้ตั้งค่า (เจ้าของร้านเลือกแบบนี้)
- หลังแตะ เข้า `PickTransition` เดิม แล้วไปหน้าคำทำนายเดิม (`/reading/[cardId]` หรือ `/reading/[cardId]/reversed`) ผลที่ได้เหมือนโหมดไพ่จริงทุกประการ
- การสุ่มต้องเกิดฝั่ง client หลัง interaction เท่านั้น (ไม่สุ่มตอน render) เพื่อไม่ให้ hydration ไม่ตรงกัน

### 4.4 โหมดไพ่จริง
- ใช้กริดเลือกไพ่เดิมใน `CardGrid` (ค้นหา + สวิตช์ "ไพ่ที่ได้เป็นท่ากลับหัว") โดยไม่เปลี่ยนพฤติกรรม ยกเว้นย้ายเส้นทางหรือหัวข้อให้เข้ากับ flow ใหม่ได้

### 4.5 หน้าผลลัพธ์
- ปุ่มหลักเหลือ 2 อย่าง
  1. **แชร์/ดาวน์โหลด** (ปุ่มแชร์ลง IG story และดาวน์โหลดที่มีอยู่ใน `PosterActions`)
  2. **เล่นใหม่** พากลับไปหน้าเลือกโหมด
- แทนที่ลิงก์ "เลือกไพ่ใหม่" เดิมด้วย "เล่นใหม่"

### 4.6 เมนู / SiteNav
- ซ่อน **หน้า character ทั้ง 22 ตัว** ไว้ในเมนูมุมจอ ไม่เป็นปุ่มเด่นบนหน้าแรก
- ลบลิงก์ซ้ำ ("เลือกไพ่" ที่ `/pick` ใน nav)
- โลโก้ "✦ Handroll Tarot" กลับหน้าแรกเหมือนเดิม
- รายละเอียดเมนู (hamburger/dropdown ฯลฯ) ให้ผู้ทำเลือก ขอให้เปิดด้วยมือเดียวบนมือถือได้ และมี a11y พื้นฐาน (focus, label)

## 5. แอนิเมชันสับสำรับ (เจ้าของร้านมอบให้ออกแบบ)

เป้าหมาย: ดูเหมือนสับไพ่จริง มีลูกเล่น ใช้เวลารวมไม่เกิน ~1.5 วินาที (ไม่นับช่วงแผ่พัดที่ผู้ใช้โต้ตอบต่อ) กดข้ามได้ตลอด

**ลำดับที่เสนอ (เป็นข้อเสนอ ผู้ทำปรับรายละเอียดได้):**
1. **แยกสำรับ:** สำรับกองเดียวแยกเป็น 2 ฝั่งซ้าย/ขวา (ขยับ `x`, หมุน `rotate` เล็กน้อย)
2. **Riffle:** ไพ่จากสองฝั่งสลับตกลงมาซ้อนกันทีละใบ 6–10 ใบ (stagger เล็กๆ ใช้ไพ่แต่ละ layer เป็นแค่ div ซ้อนกัน ไม่ต้องเรนเดอร์ครบ 22 ใบ) มีเงา/แสงกระพริบเบาๆ ตอนชนกัน
3. **รวมกอง:** สองฝั่งรวมเป็นกองเดียวพร้อมกระแทกเบาๆ (scale/translateY สั้นๆ)
4. **แผ่เป็นพัด:** ไพ่ 22 ใบกระจายออกเป็นพัด (แต่ละใบ `rotate` + `x`/`y` ต่างกัน, stagger ~15–25ms) ใบที่โดน hover/แตะยกขึ้นเล็กน้อย

**ข้อกำหนดทางเทคนิคสำหรับผู้ทำ**
- ใช้ Framer Motion และ animate เฉพาะ `transform`/`opacity` (ห้ามแอนิเมต `width`/`height`/`top`/`left`/`box-shadow`/`filter` ที่ทำให้ layout/paint หนัก ถ้าอยากได้เงาให้ใช้ element แยกแล้วเปลี่ยน `opacity`)
- ระหว่างสับ ใช้ใบหลอกจำนวนน้อย (ประมาณ 8–12 div) ตอนแผ่พัดจึงค่อยแสดงครบ 22 ใบ เพื่อความลื่นบนมือถือระดับกลาง
- ใช้ `CardBack` เดิมจาก `components/art/CardFace.tsx` เป็นหลังไพ่
- ทุกใบที่เห็นในพัดต้องเป็นคว่ำ (ห้ามรั่วว่าใบไหนคือใบไหน)
- กดที่ใดก็ได้บนฉากสับ หรือปุ่ม "ข้าม" เพื่อไปที่พัดทันที
- `prefers-reduced-motion`: ข้ามสับไปเป็นพัดที่แสดงทันที (ใช้ `MotionProvider` / `MotionConfig reducedMotion="user"`) และห้ามเช็ก `useReducedMotion` ใน `initial` ของคอมโพเนนต์ที่ SSR
- ไพ่ในพัดต้องกดได้ด้วยคีย์บอร์ดและมี `aria-label` (เช่น "ไพ่ใบที่ N")
- หลังเลือกแล้วห้ามกดซ้ำระหว่างเล่น `PickTransition` (เหมือนเดิมที่ `CardGrid` ทำ)
- ต้องไม่เล่นแอนิเมชันซ้ำเมื่อกลับมาหน้านี้จาก cache (Activity) ดูวิธีล้าง state ใน `CardGrid` เป็นตัวอย่าง

## 6. สิ่งที่ปล่อยให้ผู้ทำตัดสินใจ
- ชื่อ route (เสนอ: `/play` เลือกโหมด, `/draw` จั่วบนเว็บ, `/pick` ไพ่จริงคงเดิม)
- ดีไซน์เมนู, ขนาด/รูปแบบพัดบนจอเล็ก (22 ใบซ้อนกันอย่างไรให้แตะได้), ข้อความไทยบนปุ่มและหน้าเลือกโหมด
- วิธีสุ่ม (`crypto.getRandomValues` หรือ `Math.random` ก็ได้ เพราะเพื่อความบันเทิง) และ Fisher–Yates สำหรับสับ
- การเขียนเทสต์ของฟังก์ชันสุ่ม/สับ (เสนอให้แยกเป็นฟังก์ชัน pure ใน `data/` หรือ `lib/` ที่รับตัวสุ่มเข้าไปได้ ทดสอบด้วย Vitest ที่มีอยู่)

## 6.1 การตัดสินใจของผู้เขียน spec (ไม่ใช่สิ่งที่เจ้าของร้านเลือกเอง — ตรวจได้)
- **ไพ่ที่จั่วเก็บใน client state ได้:** ลำดับที่สับแล้ว (cardId + กลับหัวหรือไม่ ต่อตำแหน่ง) เก็บใน React state ฝั่ง client ได้ ความลับที่ต้องรักษามีแค่ใน DOM คือหลังไพ่ในพัดต้องไม่มี cardId/ชื่อไพ่ใน attribute, `aria-label` ("ไพ่ใบที่ N" เท่านั้น) หรือ `key` ที่อ่านออก
- **`PickTransition` ใช้ซ้ำโดยไม่แก้:** รับ `card`, `reversed`, `onDone` อยู่แล้ว โหมดจั่วบนเว็บส่งค่าที่สุ่มได้เข้าไปตรงๆ แล้วไปเส้นทางคำทำนายเดิม
- **กลับมาหน้าจั่ว (เล่นใหม่ / ปุ่ม Back / กลับจาก cache):** ได้สำรับใหม่ที่ยังไม่สับ ไม่คืนพัดเดิม เพื่อกันการจั่วซ้ำจากพัดเดิม
- **เมนู/นำทาง:** เมนูมุมจอแสดงทุกหน้า ยกเว้นระหว่าง `PickTransition` เต็มจอ หน้า "ไพ่จริง" และหน้า "จั่วบนเว็บ" มีลิงก์เล็กๆ "เปลี่ยนโหมด" กลับหน้าเลือกโหมด
- **อัตรากลับหัว 30%:** เป็นค่าคงที่เดียวใน `data/` (ตามกฎ CLAUDE.md ที่ให้ค่าที่ร้านปรับได้อยู่ใน `data/`) ไม่มีสวิตช์ในหน้าเว็บ
- **คำทำนายเหมือนกันทั้งสองโหมด:** ถือว่าเป็นจริงโดยโครงสร้าง เพราะทั้งสองโหมดไปเส้นทางคำทำนายเดียวกัน ไม่ต้องมีเทสต์เพิ่มนอกจากเทสต์ฟังก์ชันสุ่ม/สับ

## 7. ต้องอัปเดตเอกสารด้วย
- `CLAUDE.md`: แก้ประโยค "เว็บไม่สุ่มไพ่" ให้เป็น "โหมดไพ่จริงเว็บไม่สุ่ม ส่วนโหมดจั่วบนเว็บสุ่ม" อัปเดต User flow และโครงสร้าง `app/`
- `AGENTS.md`/README ถ้ามีการอ้างถึงเส้นทางที่เปลี่ยน

## 8. เกณฑ์ผ่าน
- Landing มีปุ่มหลักปุ่มเดียว หน้าเลือกโหมดมี 2 ตัวเลือกชัดเจน
- ไม่มีปุ่ม/ลิงก์ที่พาไปปลายทางเดียวกันซ้ำในหน้าเดียวกัน
- โหมดจั่วบนเว็บ: สับ → พัด → แตะ 1 ใบ → `PickTransition` → คำทำนาย ได้ครบ และกลับหัวสุ่มได้จริง (ทดสอบเปิดหลายรอบจะเจอทั้งสองท่า)
- โหมดไพ่จริงทำงานเหมือนเดิม
- หน้าผลลัพธ์มีแค่ "แชร์/ดาวน์โหลด" และ "เล่นใหม่"
- แอนิเมชันสับ ≤ ~1.5 วินาที ข้ามได้ ลื่นบนมือถือ และ reduced-motion ข้ามได้
- `npm run lint`, `npm test`, `npm run build` ผ่าน
