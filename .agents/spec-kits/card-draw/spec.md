(Web Card Draw Mode & Flow Streamlining)

- **Feature**: โหมดจั่วไพ่บนเว็บ (สุ่มไพ่) และจัดระเบียบปุ่มนำทางทั้งระบบ

- **Target Branch**: `feature/draw-card`

## 1. ที่มาและปัญหา (Background & Problem Statement)

เว็บดูดวงไพ่ทาโร่ต์ร้านแฮนโรล Callsati ปัจจุบันมีข้อจำกัดในการใช้งานจริง 2 ประเด็นหลัก:
1. **ไม่รองรับกรณีไม่มีไพ่จริง**: เดิมมีเพียง Flow เดียวคือ "ลูกค้าต้องจั่วไพ่จริงที่ร้าน แล้วมาเลือกบนเว็บว่าได้ใบไหน" แต่ผู้จัดกิจกรรมต้องการให้ลูกค้าหรือผู้จัดสามารถกดเล่นจั่วไพ่บนเว็บได้โดยตรงเมื่อไม่มีสำรับไพ่จริง
2. **ปุ่มซ้ำซ้อนและสร้างความสับสน**:
   - หน้า Landing (`Hero.tsx`) และแถบนำทาง (`SiteNav.tsx`) มีปุ่มพาไปยัง `/pick` และ `/characters` ซ้ำกัน
   - หน้าผลลัพธ์มีลิงก์ "เลือกไพ่ใหม่" ซึ่งไม่สะท้อนถึงการเล่นในโหมดจั่วบนเว็บ

## 2. เป้าหมาย (Goals) และสิ่งที่ไม่ทำ (Non-Goals)

### เป้าหมาย (Goals)
1. เพิ่มโหมดจั่วไพ่บนเว็บ (`/draw`) โดยเว็บเป็นผู้สุ่มไพ่ 1 ใบ พร้อมแอนิเมชันสับสำรับ (<= 1.5 วินาที) และแผ่พัด 22 ใบ
2. คงโหมดไพ่จริงเดิม (`/pick`) ให้ใช้งานได้สมบูรณ์เช่นเดิม
3. สร้างหน้าเลือกโหมด (`/play`) เพื่อให้ผู้ใช้เลือกโหมดก่อนเริ่มเล่น
4. ปรับลดความซ้ำซ้อนของปุ่มนำทาง (Landing เหลือปุ่ม "เริ่ม", SiteNav ซ่อน Character ไว้ในเมนูมุมจอ, หน้าผลลัพธ์มีปุ่ม "เล่นใหม่")

### สิ่งที่ไม่ทำ (Non-Goals)
- ไม่แก้ไขข้อมูลไพ่ 22 ใบ, คำทำนาย 4 หมวด, ซอส 4 ชนิด, Character และตาราง mapping ใน `data/`
- ไม่ทำระบบล็อกอิน, ไม่เก็บสถิติ, ไม่จำโหมดข้ามรอบ (ถามใหม่ทุกรอบ)
- ไม่เพิ่มจำนวนไพ่ที่จั่ว (จั่วครั้งละ 1 ใบเท่านั้น)

### Anti-Goals (ข้อที่ถือว่าไม่ผ่าน)
- ผู้จัดหรือลูกค้ายังสับสนว่าปุ่มไหนพาไปไหน
- แอนิเมชันสับไพ่นานเกิน 1.5 วินาที, ล็อกการกดข้าม, หรือกระตุกบนมือถือ
- คำทำนายของไพ่ใบเดียวกันในโหมดจั่วบนเว็บต่างจากโหมดไพ่จริง

## 3. รายละเอียดการทำงานของระบบ (Functional Requirements)

### FR-1: Landing Page (`/`)
- มีปุ่มหลัก (Primary CTA) เพียงปุ่มเดียว: ข้อความ "เริ่ม" นำทางไปยัง `/play`
- ตัดลิงก์ "ดู character ทั้ง 22 ตัว" ออกจากหน้าแรก เพื่อไม่ให้แย่งความสนใจ

### FR-2: หน้าเลือกโหมด (`/play`)
- แสดงการ์ด/ปุ่มตัวเลือกขนาดใหญ่ 2 ตัวเลือก:
  1. **จั่วบนเว็บ**: ไม่ต้องใช้ไพ่จริง กดสุ่มบนเว็บได้ทันที -> ไปยัง `/draw`
  2. **เลือกไพ่ที่จั่วจริง**: ผู้จัดสับไพ่จริงแล้วเลือกว่าได้ใบไหน -> ไปยัง `/pick`
- ไม่บันทึกประวัติโหมด เพื่อให้เริ่มรอบใหม่ได้เป็นอิสระทุกครั้ง

### FR-3: โหมดจั่วบนเว็บ (`/draw`)
- **การเริ่มสำรับ**: เริ่มต้นด้วยกองไพ่คว่ำ 1 กอง พร้อมปุ่ม/ข้อความให้แตะเพื่อเริ่มสับ
- **แอนิเมชันสับไพ่**: แอนิเมชัน Riffle + รวมกอง ไม่เกิน 1.5 วินาที สามารถกดแตะข้ามได้ตลอดเวลา และหากผู้ใช้เปิด `prefers-reduced-motion` ให้ข้ามไปยังพัดไพ่ทันที
- **พัดไพ่ 22 ใบ**: แผ่ไพ่คว่ำ 22 ใบในรูปพัด ไพ่แต่ละใบรองรับการสัมผัส (touch), hover (ยกขึ้นเล็กน้อย) และเข้าถึงได้ผ่าน Keyboard (`tabIndex={0}`, `aria-label="ไพ่ใบที่ N"`)
- **ความปลอดภัยของข้อมูลใน DOM**: ห้ามมี `cardId`, ชื่อไพ่, หรือข้อมูลเปิดเผยหน้าไพ่ใน DOM attribute หรือ key ของพัดไพ่
- **การสุ่มไพ่และการกลับหัว**:
  - สุ่มลำดับไพ่ 22 ใบด้วย Fisher–Yates Shuffle เมื่อเริ่มสับ (Client-side interaction only เพื่อป้องกัน hydration mismatch)
  - สุ่มท่ากลับหัว (Reversed) อัตโนมัติที่ความน่าจะเป็น 30% (กำหนดค่าคงที่ไว้ใน `data/`)
  - ตำแหน่งไพ่ที่ผู้ใช้เลือกในพัดจะตรงกับ index ในสำรับที่สับไว้
- **การเชื่อมต่อ Transition**: เมื่อแตะเลือกไพ่ ส่งข้อมูลไพ่และท่ากลับหัวเข้าสู่ `PickTransition` เดิม แล้วนำทางไปยัง `/reading/[cardId]` หรือ `/reading/[cardId]/reversed`
- **การกลับมาหน้าเดิม**: เมื่อผู้ใช้กดย้อนกลับ หรือกลับมาจาก Activity/Cache ต้องรีเซ็ตสำรับเป็นกองใหม่ที่ยังไม่สับเสมอ

### FR-4: โหมดไพ่จริง (`/pick`)
- คงการทำงานของ `CardGrid` เดิม (ค้นหาชื่อไพ่ + สวิตช์สลับไพ่กลับหัว + `PickTransition`)
- เพิ่มลิงก์ "เปลี่ยนโหมด" ขนาดกะทัดรัดเพื่อกลับไปยัง `/play`

### FR-5: หน้าผลลัพธ์คำทำนาย (`/reading/...`)
- ปรับปุ่ม Action หลักให้เหลือ 2 ปุ่มชัดเจน:
  1. **แชร์/ดาวน์โหลด**: สร้างภาพโปสเตอร์ IG Story 1080×1920 (ตามที่มีอยู่ใน `PosterActions`)
  2. **เล่นใหม่**: ลิงก์พากลับไปยังหน้าเลือกโหมด (`/play`) แทนที่ข้อความ "เลือกไพ่ใหม่" เดิม

### FR-6: เมนูและการนำทาง (`SiteNav.tsx`)
- โลโก้ "✦ Handroll Tarot" คลิกแล้วกลับหน้าแรก (`/`)
- ลบลิงก์ซ้ำ "เลือกไพ่" ออกจาก Navbar
- ปรับลิงก์ "Character ทั้ง 22 ตัว" ให้เข้าไปอยู่ในเมนูมุมจอ (Dropdown / Drawer) ที่เปิดได้ง่ายด้วยมือเดียวบนมือถือ พร้อม a11y ครบถ้วน (Escape to close, focus trap/outline)

## 4. ข้อกำหนดเชิงเทคนิคและข้อจำกัด (Non-Functional Requirements)

- **NFR-1 (Mobile-First)**: รองรับหน้าจอมือถือความกว้างตั้งแต่ 360px ขึ้นไปอย่างสวยงาม
- **NFR-2 (Animation Performance)**: ใช้ Framer Motion แอนิเมตเฉพาะ `transform` และ `opacity` เท่านั้น (ห้ามแอนิเมต layout properties เช่น width, height, top, left)
- **NFR-3 (Accessibility)**: รองรับ `prefers-reduced-motion` ผ่าน `MotionProvider`, มี `aria-label`, รองรับ keyboard navigation
- **NFR-4 (Next.js 16 & Hydration)**: ห้ามเรียกสุ่มค่าสุ่มระหว่าง SSR render ให้สุ่มเฉพาะเมื่อเกิด Client Event; รองรับ `cacheComponents` / Activity
- **NFR-5 (Domain Layer Separation)**: ค่าคงที่อัตราสุ่มกลับหัว (30%) และฟังก์ชันสับไพ่ต้องอยู่ใน `data/` แยกจาก UI components
